- Playlist building lives only in src/lib/playlist (organize.ts for whole-library grouping, vibe.ts for single vibe playlists, both reusing compatibility()/sequence()); no other playlist engine — avoids engines with conflicting rules.
- Spotify access goes only through the server connection (spotify-auth-start/callback, tokens in spotify_connections); no browser-side Spotify client — one token source, no client secret exposure.
- Spotify calls follow the Feb 2026 Development Mode API (/me/playlists, /playlists/{id}/items, single-item GETs, no audio-features/top-tracks/popularity) — those endpoints/fields are gone.
- Artist genres and AI track classification are filled only by the library-enrich background function (started after each sync, pauses on long Spotify waits); the browser only reads stored data — keeps playlist creation instant and avoids blocking on Spotify rate limits.
- Listener evidence (Last.fm tags, YouTube comment summaries) is gathered only by the listener-tags background function, kicked when library-enrich finishes; it re-describes feeling with the strong model and never overrides manual_sound — one evidence pipeline, bounded API quotas.
- Song analysis is shared across users in track_analysis_global (filled by triggers on track_ai_classification/listener_evidence; copied back with hydrate_track_analysis before any AI call); manual_sound and feedback stay per user — one analysis per Spotify id, no repeated AI cost.
- Pre-built AI Playlists are produced by src/lib/playlist/prebuild.ts (usePrebuild in AppLayout, DB lease in prebuilt_playlists) using organize.ts, and the AI Playlists page reads the saved set first — instant page, still one engine.
- Each vibe run logs per-step durations to vibe_timings — keeps the <20 s target measurable.
- Song SOUND heard from public previews (Deezer by ISRC, then iTunes) is produced only by the audio-analyze background function into the shared track_audio_analysis table (vibe-listen hears clips on demand); audio is never stored, it overrides text sound fields but never feeling/arc or manual_sound — one listening pipeline, preview terms must be reviewed before public launch.
- Seeded vibes are decided by the ear: vibe-listen hears the 40 closest songs in stored sound (15 s mid-clip, batches of 8, all requests at once) against the seed whose feeling matches each song; ear 8+ with feeling match admits without the coherence check, which stays only for text-scored (no-clip) songs; the recipe runs in parallel only for the name — one judge per song, nothing waits on the recipe.
- Free-text vibes (no seed) are interpreted by vibe-spec into a rich recipe (vocals, listening, moment, instrument include/exclude, warmth/texture/drive/focus ranges, feelings_allowed, one-shot clarify question); the panel shows it as editable "Lo que entendí" chips, edits persist to vibe_spec_corrections and win on exact phrase match, and vibe-listen's description mode (no seed) is the judge — text review only for songs without a clip.
